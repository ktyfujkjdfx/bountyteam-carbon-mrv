# Carbon Lens — граница интеграции интерфейса

Документ для Backend (G0), Trust и Team Lead. Он перечисляет всё, что интерфейс `/lens` сейчас
предполагает о будущем контракте, и всё, что в нём помечено как временное. Без этого списка
подключение живого сервиса превращается в угадывание.

Владелец файла: Frontend. Область записи — только `frontend/`.

## 1. Что интерфейс читает сам, а что получает от сервиса

| Источник | Что берётся | Где в коде |
|---|---|---|
| `data/areas.csv`, `data/areas.geojson` | список участков, регион, площадь, годы анализа, `baseline_id`, bbox, контур | `src/lens/adapter.ts` |
| `data/sample_requests.geojson` | официальный подучасток `CHECK_TRANSFER_01`, правило базовой линии родителя | `src/lens/adapter.ts` |
| `data/scenes.csv` | сцены Sentinel-2: дата, идентификатор, облачность сцены, доля пикселей SCL 4–7 | `src/lens/data.ts` |
| `data/events.csv` | записи о внешних продуктах гарей: даты, погрешность, число пикселей, ограничения, ссылка | `src/lens/data.ts` |
| `data/methodology/baseline.csv` | базовая линия по годам, темп истории 2015–2019 | `src/lens/data.ts` |
| `data/methodology/parameters.csv` | CF, 44/12, вычет 0.10, порог H/R, резерв 0.15, утечка, цены 500/1500/4000, годы истории и горизонта | `src/lens/data.ts` |
| `data/sources.csv` | продукты, версии, лицензии, DOI, требуемая атрибуция, дата доступа, ограничения | `src/lens/data.ts` |
| **Сервис (после G0)** | запас, ΔC, E, базовая линия в CO₂-экв., неопределённость, R, вычеты, резерв, округление, **Q**, покрытие, зоны, артефакты, паспорт | `src/lens/httpClient.ts` |

Интерфейс **не вычисляет** научные величины. Единственная арифметика на экране — умножение уже
полученного Q на сценарную цену из `parameters.csv` и вычитание Q из введённого пользователем
заявления. Ни то, ни другое не меняет Q.

## 2. Граница адаптера

```ts
interface LensApiClient {
  kind: 'fixture' | 'http';
  listAreas(): Promise<LensArea[]>;
  getAreaGeometry(aoiId: string): Promise<LensGeometry>;
  measureArea(geometry: LensGeometry): Promise<number>;
  submitAnalysis(request: LensRequest, options: LensSubmitOptions): Promise<LensJob>;
  getJob(jobId: string, signal?: AbortSignal): Promise<LensJob>;
  getResult(resultId: string, signal?: AbortSignal): Promise<LensResult>;
}
```

После публикации G0 заменяются `src/lens/httpClient.ts`, `src/lens/types.ts` и генерация типов.
Компоненты экрана не меняются: они принимают `LensResult` и ничего не знают об источнике.

## 3. Предположения о контракте (ASSUMPTION — требуют подтверждения Backend)

| № | Предположение | Что будет, если Backend решит иначе |
|---|---|---|
| A1 | Базовый путь `/api/v2`, маршруты `GET /areas`, `GET /areas/{id}/geometry`, `POST /areas/measure`, `POST /analyses`, `GET /jobs/{id}`, `GET /results/{id}` | меняется только `httpClient.ts` |
| A2 | Задание: `job_id`, `state` ∈ QUEUED/RUNNING/SUCCEEDED/FAILED, `status_url`, `result_id`, `error {code, message}` | меняется маппинг задания, опрос сохраняется |
| A3 | Идемпотентность запуска — заголовок `Idempotency-Key`; повтор того же намерения возвращает то же задание | иначе двойной клик создаст два расчёта |
| A4 | Авторизация — заголовок `X-Lens-Token` со значением, выдаваемым во время сессии; никаких секретов в сборке | нужен другой заголовок или схема — правка в одном месте |
| A5 | CORS разрешает `GET, POST` и заголовки `Content-Type, X-Lens-Token, Idempotency-Key` для точного origin SPA | запросы из браузера не пройдут |
| A6 | Оси статусов независимы: `calculation_status`, `evidence_status`, `claim_status`, состояние задания | склеенный «общий рейтинг» интерфейс показать не сможет |
| A7 | `units.q` — целое или `null`; при `null` заполняется причина недоступности, при `0` — причина нуля; перечни причин раздельные | иначе «ноль» и «нет данных» сольются, что запрещено постановкой |
| A8 | Неокруглённые промежуточные величины приходят отдельно: `r_tco2e`, `h_tco2e`, `h_over_r`, `unc_fraction`, `r_adj_tco2e`, `buffer_tco2e`, `leakage_tco2e`, `rounding_remainder_tco2e` | разбор расчёта нельзя будет показать без пересчёта на клиенте |
| A9 | `coverage[]` содержит три независимые оси: `BIOMASS_CCI`, `BASELINE_TABLE`, `OPTICAL_PAIRED_VALID`, каждая с долей и площадью пропуска | оптика и биомасса перепутаются |
| A10 | `area_ha` считает сервис; клиентская сферическая оценка — только предварительный показ | см. раздел 5 |
| A11 | `zones[]` могут содержать `geometry` (Polygon/MultiPolygon) и `evidence_event_id`, ссылающийся на строку `data/events.csv` | без геометрии зоны рисуются маркерами, без `event_id` доказательство не связывается |
| A12 | `artifacts[]`: `artifact_id`, `role`, `media_type`, `sha256`, `url` (начинается с `/api/v2/`), `bbox`, `crs`, `resolution_m`, `unit`, `provenance`; браузер получает PNG/WebP/GeoJSON, не GeoTIFF | превью не отобразится |
| A13 | `passport.content_sha256` — хеш содержимого, **не включающий сам себя**; дата запуска отделена от детерминированного содержимого | проверка целостности станет невозможной (см. раздел 6) |
| A14 | `optical.scene_keys` ссылается на `scene_key` из `data/scenes.csv`; метаданные сцен интерфейс берёт из таблицы | придётся передавать метаданные сцен в ответе |
| A15 | Ошибка приходит конвертом `{ error: { code, message, details? } }` | сообщение пользователю станет менее конкретным |
| A16 | `layers[]` может приходить от сервиса; если его нет, интерфейс строит описание слоёв сам | дублирование описаний слоёв |

## 5. Известные ограничения интерфейса

1. Площадь нарисованного или импортированного контура оценивается сферической формулой в адаптере.
   Для официального подучастка `CHECK_TRANSFER_01` расхождение с паспортными 808,8538 га — около 0,3 %.
   Авторитетное значение должен возвращать сервис (`measureArea` / `area_ha`).
2. Растровые превью в режиме помеченных данных отсутствуют: слой сообщает «нет в этом режиме».
3. Маска оптического качества и растр гарей в браузер не выдаются; показываются табличные метаданные.
4. Путь `/lens` требует SPA-fallback на сервере; офлайн-сборка открывается через `index.html#/lens`.
5. История расчётов живёт в `sessionStorage` вкладки: не синхронизируется между устройствами и не
   является реестром выпуска единиц.

## 6. Проверка целостности паспорта

`passportContent()` сериализует содержимое **без** поля `content_sha256`; `passportPayload()`
добавляет блок `integrity`. Проверка пересчитывает SHA-256 блока `content` и сравнивает с
`integrity.content_sha256`. Поэтому:

- сервис обязан считать хеш по тем же правилам (иначе каждый файл будет «изменён»);
- дата запуска и любые недетерминированные поля не должны попадать в хешируемое содержимое;
- совпадение хеша означает неизменность файла, а не истинность расчёта и не защиту от повторной продажи.

## 7. Порядок подключения после G0

1. Backend публикует `contracts/v2` и фикстуры контракта; Frontend генерирует типы отдельно от v1.
2. В `src/lens/types.ts` провизорные типы заменяются сгенерированными.
3. В `src/lens/httpClient.ts` правятся пути, имена полей и заголовок авторизации по факту контракта.
4. Запуск: `VITE_LENS_API_MODE=http`, `VITE_LENS_API_BASE_URL=<origin>/api/v2`, токен передаётся
   параметром `?token=` или вводится в панели «Доступ к сервису».
5. Проверяются: CORS, идемпотентность, опрос задания, артефакты с целостностью, поведение при
   404/503 одного артефакта, неизвестные значения перечислений.
6. Помеченный набор остаётся доступным по `?lensapi=fixture` для офлайн-показа и регрессии. Он
   никогда не подставляется автоматически вместо ответа сервиса.
