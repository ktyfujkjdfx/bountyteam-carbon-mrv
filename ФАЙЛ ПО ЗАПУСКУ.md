# Carbon Lens — запуск и воспроизведение расчёта

Сервис инвестиционной проверки лесных углеродных проектов по спутниковым данным. Отвечает не
«сколько углерода в лесу», а **подтверждаются ли заявленные единицы**. Не хватает данных —
`Q = null`; эффект не превышает базовую линию — `Q = 0`.

Проверено на коммите `e298320`, Windows 10, Python 3.12.5, Node 24.18.0.

## Что внутри

| Каталог | Что это |
|---|---|
| `data/`, `doc/` | официальные данные и методика кейса — **уже в репозитории, докачивать нечего** |
| `rs/` | растры, площади, покрытия, ячейки, зоны изменений, разрывы наблюдений |
| `carbon/` | методика: Eproj, Ebase, R, H, UNC, Radj, B, Q, claims, паспорт, хеши |
| `backend/` | FastAPI: API v2, роли, жизненный цикл заявки, артефакты, отчёты |
| `frontend/` | интерфейс `/lens` для трёх ролей |
| `contracts/` | единственный источник схем и OpenAPI |

## Требования

Python 3.12 или 3.13, Node 24 (версия в `.nvmrc`), Chrome или Edge, ~2 ГБ диска. Интернет для
расчёта не нужен.

## Установка

```bash
git clone https://github.com/ktyfujkjdfx/bountyteam-carbon-mrv
cd bountyteam-carbon-mrv && git switch integration/carbon-lens-v2

python3.12 -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements-contracts.txt -r backend/requirements-backend.txt
cd frontend && npm ci && cd ..
```

Зависимости: `requirements-contracts.txt` (numpy, rasterio, shapely, pyproj, Pillow,
jsonschema, rfc8785, PyYAML, pytest) и `backend/requirements-backend.txt` (fastapi, uvicorn,
httpx, web3). У `rs/` и `carbon/` своих зависимостей нет.

На Windows PowerShell: `.\.venv\Scripts\python.exe`, `npm.cmd`, `$env:PYTHONUTF8='1'`.

## Запуск

```bash
export PYTHONUTF8=1
export BACKEND_DEMO_SESSION=carbon-lens-demo-session-2026      # >= 16 символов
export BACKEND_LENS_DEMO_ACCOUNTS=1                            # вход по кнопке
export BACKEND_LENS_DEMO_PASSWORD_OWNER=owner-demo-2026        # >= 12 символов
export BACKEND_LENS_DEMO_PASSWORD_VERIFIER=verifier-demo-2026
export BACKEND_LENS_DEMO_PASSWORD_INVESTOR=investor-demo-2026
export BACKEND_LENS_ENGINE_MODE=REAL
export BACKEND_LENS_REQUIRE_REAL=1                             # лучше не подняться, чем соврать
export BACKEND_CORS_ORIGINS=http://127.0.0.1:5173,http://localhost:5173

./.venv/Scripts/python.exe -m backend.migrate
./.venv/Scripts/python.exe -m backend.serve --host 127.0.0.1 --port 8031

cd frontend && npm run dev        # http://127.0.0.1:5173
```

Открыть **`http://127.0.0.1:5173/lens?demo=1`** — три кнопки ролей, пароль подставляет сервис.
Учётные записи: `owner`, `verifier`, `investor`. Существующий аккаунт сервис не пересоздаёт.

Адрес сервиса для интерфейса задаётся в `frontend/.env.local` (не в гите):
`VITE_LENS_API_BASE_URL=http://127.0.0.1:8031/api/v2`.

## Воспроизведение расчёта

**В браузере:** владелец выбирает участок (`RU_TVER_01`), период 2019–2024, объём 1000 →
отправляет; верификатор запускает расчёт, дожидается `SUCCEEDED`, подтверждает паспорт;
инвестор видит подтверждённый результат и выгружает отчёт.

**Без браузера, весь путь одной командой:**

```bash
LIVE_REQUIRED=1 ./.venv/Scripts/python.exe -m backend.tools.live_composition
```

Падает, а не подставляет заглушку, если `rs.case2` или `carbon` недоступны.

**По HTTP:** `POST /auth/demo-login` → `POST /requests` → `POST /requests/{id}/submit` →
`POST /requests/{id}/analysis` (только верификатор, с `Idempotency-Key`) → опрос
`GET /analyses/{id}` до `SUCCEEDED` → `POST /requests/{id}/finalize`.

## Входы и выходы

Вход: `{"aoi_id":"RU_TVER_01","year_start":2019,"year_end":2024,"claimed_units":1000}`. Вместо
`aoi_id` можно прислать `geometry` (Polygon/MultiPolygon, WGS84) — новый контур работает без
правки кода, предел 2000 га проверяет сервис.

Выход: `units.q` (`0` — корректный ноль, `null` — данных не хватило) с `zero_reason`;
`uncertainty.interval_kind: SCENARIO` и `sensitivity[]`; четыре покрытия плюс
`coverage_fraction_raw`; `zones[]` с причиной, периодом с погрешностью в днях и вкладом зоны
в итог; `claim`; `limitations[]`; `sources[]` с версией и лицензией; `artifacts[]` —
ячейки CCI, зоны, разрывы, снимки до/после, dNBR и две маски, каждый со своим sha256.

Отчёт: `GET /analyses/{id}/report` → `{"content": …, "integrity": {content_sha256, report_sha256}}`.

## Проверка целостности отчёта

```python
import hashlib, json, rfc8785
r = json.load(open("carbon-lens-77dbe9c7e45a.json", encoding="utf-8"))
print("0x" + hashlib.sha256(rfc8785.dumps(r["content"])).hexdigest() == r["integrity"]["content_sha256"])
```

Проверено: сходится. Измените любое число в файле — перестанет. То же делают кнопки
«Проверить научное содержание» и «Проверить хеш отчёта».

## Если не поднялось

- сервис ругается на `BACKEND_DEMO_SESSION` — он короче 16 символов;
- нет кнопок ролей — не задан `BACKEND_LENS_DEMO_ACCOUNTS=1` или открыт адрес без `?demo=1`;
- браузер не достучался — origin не указан в `BACKEND_CORS_ORIGINS`;
- нарисованный контур отклонён — предел 2000 га или выход за данные кейса, приблизьте карту;
- карта выглядит пустой — так и задумано: внешние подложки не загружаются, вместо них сетка.

## Чего нельзя

Подменять `data/` и `doc/`; менять методику (`Q = floor(Radj × 0.85)`, `CO₂/C = 44/12`,
базовая линия из `data/methodology/baseline.csv`); подправлять реальные `Q = 0`; называть
сценарный интервал доверительным; выдавать fixture за расчёт.
